# 0003. トークンを安全に保存し、自動で更新する

- 日付: 2026-10-27
- 状態: 採用

## 背景

- トークンの有効期限は 1 ヶ月と 1 日。再発行 API がある。
- 環境変数で渡すだけだと、毎月手作業で更新が必要になる（類似 MCP の弱点）。
- 手元の PC だけでなく、キーチェーンのないサーバー上のボットからも使いたい。

## 決定

- 保存先は OS のキーチェーン（`@napi-rs/keyring`）。使えない環境では本人のみ読み書きできるファイル（パーミッション 600）。
- Linux では Secret Service を明示指定する。未指定だとカーネルのキーリングに黙って切り替わり、再起動で消えるため。
- 環境変数は、保存先が空のときのそのプロセス限りの認証に使う。保存と、期限不明のときの再発行は `KINTAI_PLUS_PERSIST_ENV_TOKEN=true` のときだけ（2026-10-29 改訂。詳細は ADR 0007）。保存先に認証情報があるときは、環境変数より保存先を優先する。
- 有効期限の残りが 15 日（設定可）を切ったら再発行する。最後の 15 日間に 1 回でも使われれば失効しない。
- 複数プロセスでの二重更新はロックで防ぎ、更新前に保存先を読み直す。

## 結果

- トークンが URL のクエリに載る API 仕様のため、ログ・エラーからのトークン除去を必須とする。
