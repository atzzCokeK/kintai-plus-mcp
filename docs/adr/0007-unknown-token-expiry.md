# 0007. 環境変数のトークンは、明示しない限り保存も再発行もしない

- 日付: 2026-10-27（2026-10-29 に改訂）
- 状態: 採用

## 背景

- 自動更新（ADR 0003）は有効期限の残りで判断する。`login` で貼り付けたトークンは、いつ発行されたかわからない。
- トークン単体から期限を知る API は見当たらない。再発行 API の応答には、新しいトークンと `expired_at` がある。
- 再発行すると、その呼び出しに使ったトークンは使えなくなる。環境変数だけを渡す利用者（CI やボット）は、その値を他のプロセスと共有していることが多い。初回利用で再発行すると、環境変数の値が黙って無効になる。
- 同じ値をキーチェーンやファイルへ保存すると、以降は保存先が優先され、環境変数を差し替えても反映されない。

## 決定

- `login` で登録したトークンは、登録時に再発行して期限を保存する。再発行に失敗したときは期限不明のまま保存し、次の利用時に再発行を試みる。`KINTAI_PLUS_AUTO_REFRESH=false` なら再発行しない。
- 環境変数 `KINTAI_PLUS_TOKEN`（と企業 ID）は、保存先が空のときそのプロセスの中だけで使う。キーチェーンやファイルには書かない。期限が不明でも再発行しない。
- 環境変数のトークンを保存し、期限が不明なら再発行する動作は `KINTAI_PLUS_PERSIST_ENV_TOKEN=true` のときだけ行う。この場合、環境変数に書いたトークンは使えなくなることがある。
- 保存済みで期限のわかるトークンは、これまでどおり残り日数で再発行する。

## 結果

- ボットは環境変数を置くだけで、トークンを無効化せずに使える。自動更新が必要なら `login` で、このサーバー専用のトークンを登録する。
- README に、再発行が環境変数のトークンを使えなくしうることと、オプトインの変数を書く。
