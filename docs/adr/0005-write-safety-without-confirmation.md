# 0005. 書き込み時は確認ダイアログを出さず、機械的な安全策で防ぐ

- 日付: 2026-10-27
- 状態: 一部を [0010](./0010-confirmation-levels.md) に移した（2026-11-03）。打刻種別の必須、矛盾チェック、`force`、読み取り専用はこの決定のまま。確認の既定と `destructiveHint` の付け方は 0010。

## 背景

- 毎回の確認は不便で、ボットからは確認ダイアログ（Elicitation）を出せない。Claude Desktop などは Elicitation 未対応。
- 打刻 API はサーバー到着時刻で記録され、API からは修正できない。誤打刻の修正には Web 画面からの申請が要る。
- 誤打刻の多くは「出勤済みなのに出勤」のような矛盾。

## 決定

- 打刻の種別は必須にし、API の「省略時に自動切り替え」は使わない。
- その日の打刻履歴と矛盾する打刻は弾く。`force: true` で実行可能。
- 読み取り専用モードを用意する。
- 確認の既定と、どの書き込みを destructive とみなすかは ADR 0010。当時の「既定では確認なし」「書き込みはすべて destructiveHint」はそこへ移した。
