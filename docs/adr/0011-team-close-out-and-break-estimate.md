# 0011. チームの締めは team_close_out にまとめ、休憩を引いた見積もりを使う

- 日付: 2026-11-03
- 状態: 採用

## 背景

- `check_attendance_issues`、`get_working_records`、`close_out`、`get_alerts` は本人分だけを返す。管理者は `get_team_stamps` を日ごとに呼ぶしかなく、打刻だけで見ると Web で修正済みの日も漏れに見えた。
- 過去日で退勤が無いと状態が「勤務中」になり、勤務時間がその日の終わりまで数えられていた。
- 勤務実績は実働と休憩を返さないことが多く（ADR 0008）、始業から終業の経過をそのまま残業の目安にすると休憩の分だけ多く出る。
- 出勤の重複や、出勤が無く休憩戻・退勤だけの日は、既存の打刻漏れでは拾えない。同姓同名は staffId でしか区別できない。打刻も実績も無い人（休職・退職の可能性）もいる。
- `/alerts` は本人分だけで、対象者を指定できない。

## 決定

- 一般管理者・企業管理者にだけ `team_close_out`（`scope=day` / `month`）を公開する。従業員向けの `close_out` の名前と引数は変えない。プロンプト `team_end_of_month` はこのツールを使う。
- 対象者を省略すると管理下の全員。勤務実績は 50 人・31 日、打刻は 1 日・50 人で分割する。判定は勤務実績を主にし、打刻は休憩の長さと打刻の形（重複、出勤無し）の補助にする。打刻漏れを消すのは出勤・退勤の打刻時刻で、開始・終了時刻だけでは消さない（ADR 0012 で明確化）。
- 対応が必要な人だけ、日付と理由を返す。名前に加え staffId と社員番号を出す。問題が無い人は人数だけ。期間中に実績も打刻も無い人は別にする。何も無ければその旨を明記する。
- アラートと工数の未入力はチーム分を見ない。見ていないことを結果に書く。
- 過去日で退勤（または休憩戻）が無いときは、その区間を日末まで数えない。状態は「退勤打刻なし」（または「休憩戻なし」）とする。今日の進行中はこれまでどおり、今までの時間を数える。
- 実働の項目が無いときは経過時間を残す。休憩実績があれば引き、無ければ法定の最低休憩（6 時間超で 45 分、8 時間超で 60 分）を引いた見積もりを併記し、残業の目安にはその見積もりを使う。見積もりであることは結果に書く。
- 仕様の `include_actual_working_hours_no_rounding=1` は期間指定と一緒に送る。`include_break_results=1` は `end_date` と併用できないので、1 日だけのとき追加で取る。応答に項目が無い、またはパラメータが拒否されたときは、経過時間の見積もりに落とす。これらの実応答と、管理下に無い ID を混ぜたときの挙動は未検証のままにする。
- `get_working_records` に任意の `staffIds` を足す。省略時は本人だけで、返り値から staffId を外す既存の形を保つ。

## 結果

- 管理者は 1 回の呼び出しでチームの残件を見られる。夜勤と日をまたぐ休憩は、別の日の打刻漏れや短いインターバルにしない。
- 残業の目安は、休憩を含んだ経過より小さくなる。正式な値は勤怠Plus の画面で確認する、という注意は残す。
