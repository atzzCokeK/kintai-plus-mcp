# 0009. 1日・月末の締めは close_out にまとめる

- 日付: 2026-11-02
- 状態: 採用

## 背景

- 退勤前や月末に、AI が `get_today_status`、`check_attendance_issues`、`get_manhours`、`summarize_working_hours`、`get_alerts` を順に呼ぶと、呼び出しが多く、昼休みを打刻し忘れて休憩が数分しかない日を既存の打刻漏れチェックでは見つけられない。
- 勤務実績 API は休憩を返さない（ADR 0008）。休憩の長さは打刻から計算できる。
- 過去の打刻は API で修正できない（ADR 0005）。

## 決定

- 読み取り専用の `close_out`（`scope=day` / `month`）が、優先度つきの残件を 1 回で返す。打刻・勤務実績・工数・アラートは各 1 回ずつ、並行に取る。
- 労働基準法 34 条に沿い、実働が 6 時間を超えたら休憩 45 分、8 時間を超えたら 60 分を必要とする。ちょうど 6 時間・8 時間は「超える」に含めない。
- 今日は `now` で見る。進行中を退勤漏れにしない。過去の打刻修正は `punch` ではなく Web の修正申請にする。出勤から 16 時間以内の夜勤の続きだけ、今の `punch` で閉じられる。
- 工数は打刻から求めた実働と比べ、差が 15 分を超えたら残件にする。進行中で実働 60 分未満かつ工数 0 は未入力にしない。締め・確定済みの日は `save_manhours` を案内しない。
- 残業の着地は `assessOvertimeRisk` を再利用し、`ok` のときは残件にしない。数値は目安である。
- `end_of_day` と `monthly_review` はこのツールを使う。個別ツールは詳細と書き込みのために残す。

## 結果

- 従業員向けの締めの入口は `close_out` になる。ツール名は増やさず、既存の名前も変えない。
